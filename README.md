# LogiEdge — Edge AI for Cold-Chain Fleet Monitoring

This repository is an implementation scaffold and reproducible experiment for the AIML ZG535 mini-project. The scenario and threshold values follow the supplied problem statement. **The case, sensors and generated measurements are simulated. This is not a validated pharmaceutical safety device.**

> **Do not submit unmeasured results as facts.** Training accuracy, Class 2 recall, PSI response/recovery, actual Docker layer bytes, hardware latency/power, Ansible idempotency, and demo evidence must be generated by running the project. The report template marks those values explicitly. Assignment integrity rules require the student to understand and explain their own implementation and write the final analysis using their measured results.

## Quick start (Linux/Ubuntu or Raspberry Pi OS, Python 3.11)

### Automated offline experiment run

After creating a Python 3.11 virtual environment and installing `requirements.txt`,
run from the project directory:

```bash
python run_pipeline.py --dry-run
python run_pipeline.py
```

The runner checks dependencies, runs tests, generates data, trains, converts both
INT8 variants, benchmarks, builds the confidence reference, stages Docker artifacts,
and calculates OTA costs. It uses the same interpreter throughout and works even
when launched from another directory. Each step writes a timestamped log under
`run_logs/`; inspect the active log for training progress. The first failing command
stops the pipeline without executing later steps. Running it again repeats the
experiments and may overwrite generated models/results.

Use `--variant m3` to stage the pruned INT8 model and build its matching reference;
the default is M2. This choice is not an automatic deployment recommendation.
Inspect measured accuracy and Critical recall before selecting a deployment model.
The runner does not install dependencies, start persistent services, deploy to a
remote node, fabricate report measurements, or record the demo.

After a successful run, use `docker compose build inference sync-agent` and
`docker compose up -d` to start the live stack yourself. Start the PSI monitor with
`python -m monitoring.drift_monitor` in a separate terminal before streaming data.
Follow the demo checklist for live evidence and stop the stack with
`docker compose stop` when finished.

### Individual commands

1. Install Python dependencies and start a local broker:

   ```bash
   python3.11 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   docker compose up -d mosquitto
   ```

   `requirements.txt` installs `tensorflow-cpu` on Linux/Pi and `tensorflow` on macOS
   (Apple Silicon has no `tensorflow-cpu` wheel).

2. Verify the pure preprocessing logic:

   ```bash
   python -m unittest discover -s tests -v
   ```

3. Generate the required synthetic training data and clean-data normalisation statistics:

   ```bash
   python data_pipeline/generate_dataset.py
   ```

   The generated class counts follow the selected operational-threshold policy,
   not a fixed label for an entire drift run. A vibration-only run provides
   Warning examples; later temperature-drift windows become Critical once the
   deviation exceeds 3°C. See `generation_manifest.json` for counts and the
   documented assignment conflict. The ten-minute clean source produces
   `data_pipeline/training_stats.npy`. Generated files are local experiment output.

4. Train and evaluate the FP32 MLP:

   ```bash
   python training/train_model.py
   ```

   The command fails if held-out accuracy is below the assignment's 88% gate. It writes actual metrics to `training/results/training_metrics.json`, which must be reviewed rather than edited to meet the threshold.

5. Build model variants and benchmark them:

   ```bash
   python training/convert_ptq.py
   python training/prune_quantise.py
   python optimisation/benchmark.py
   ```

   The scripts measure all five required metrics and produce `optimisation/results/benchmark_results.csv` and `pareto_chart.png`. Check Class 2 recall >95% before recommending a variant. To redraw only the chart from the existing CSV without re-measuring, run `python -m optimisation.benchmark --plot-only`.

6. Build a confidence reference using 300 independently simulated Normal windows, then run inference and monitoring:

   ```bash
   python monitoring/build_reference.py --model training/models/m2_int8.tflite
   docker compose build inference
   docker compose up -d inference
   python data_pipeline/simulator.py --truck-id truck-001 --anomaly none --duration-minutes 2
   ```

   To inject anomalies, rerun with `--anomaly combined`. The PSI monitor subscribes to inference confidence events:

   ```bash
   python -m monitoring.drift_monitor --truck-id truck-001
   ```

   Demonstrate PSI crossing 0.25 during the injected run and returning below 0.10 after clean data resumes. If the measured model does not meet these thresholds, document that result and investigate; do not fabricate a pass.

   The PSI window needs 100 inferences (about 17 minutes at real-time speed). For a shorter demonstration, replay faster with `--speed`; sensor timestamps, windows and PSI settings are unchanged:

   ```bash
   python data_pipeline/simulator.py --truck-id truck-001 --duration-minutes 30 --speed 3 \
     --anomaly combined --inject-after-seconds 510 --anomaly-after none
   ```

7. Prepare the deployment and report evidence:

   - Follow `deployment/README.md` for the two-run Ansible idempotency test.
   - Follow `inference/README.md` for the Docker model-layer cache demonstration.
   - Fill `reports/final_report_template.md` with measured outputs and original reflection, export it as `GROUPNO_LogiEdge_Final.pdf`, and verify it is 2,500–3,000 words (figures/tables/references excluded).
   - Follow `demo/demo_checklist.md` and record your own 15–20 minute run. Add the actual accessible link to `demo/demo_video_link.txt`.

## Key design calculations

- The supplied 45 MFLOPs and 18 MB per inference imply arithmetic intensity `2.5 FLOP/byte`.
- The stated Pi 5 CPU ridge point is `16 GFLOP/s ÷ 12 GB/s ≈ 1.33 FLOP/byte`; this workload is compute-bound under the Roofline assumptions. Ideal compute and memory lower bounds are about 2.81 ms and 1.50 ms respectively; real latency is hardware/runtime dependent.
- At 500 Hz, 3 axes, 4 bytes/value, plus 1 Hz temperature at 4 bytes/value, raw sensor payload is 6,004 bytes/s = 518.75 MB/day (decimal units), before protocol overhead. At ₹0.10/MB this is about ₹51.88/truck/day. The simulator publishes the specified pre-aggregated vibration RMS at 0.5 Hz, not the raw 500 Hz waveform; deployment bandwidth should be measured at the sensor gateway.
- A 280 KB model is 0.28 MB decimal. Full transfer for 85 trucks is 23.8 MB, or ₹2.38 at ₹0.10/MB. Fleet-wide total does not change under a completed canary rollout; canary stages and gates the same total. Shadow mode still requires distribution of the candidate model and additional telemetry, whose size must be measured.
- The 90-second requirement is an end-to-end detect-and-alert SLA, not a 90-second model-call budget. The project targets windowing plus inference and local alerting well below that SLA; measured end-to-end timing is required before claiming compliance.

## Known environment limits

Run only one inference container per truck ID. The Compose service and the Ansible-deployed
`logibridge-inference` container use the same MQTT client ID (`logibridge-inference-<truck_id>`);
if both run, Mosquitto keeps disconnecting one for the other and no windows are classified.
Stop the one you are not demonstrating (`docker stop logibridge-inference` or
`docker compose stop inference`).

The current authoring environment may not have TensorFlow, Docker Engine, Mosquitto, or Ansible installed. The repository includes reproducible commands and explicit runtime checks, but no model binary, benchmark measurements, live broker output, Ansible run, or demo video is fabricated. Generate those on a compatible Linux/edge environment.
