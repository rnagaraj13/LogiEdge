# A1 — FreightBridge constraint analysis

FreightBridge's pilot covers 85 refrigerated vehicles carrying temperature-sensitive cargo; the stated scale target is 265 vehicles. A refrigeration fault can raise cargo temperature by 1°C/minute, and the requirement is to detect and alert within 90 seconds of a fault signature. That deadline is end-to-end, including sensor sampling, filtering/window readiness, inference, and local annunciation. A cloud decision cannot be relied on: rural cellular round-trip time varies and includes complete 35–90-minute outages at seven route locations. Even a hypothetical 100–300 ms network RTT is only a network measurement, not a dependable bound on connection setup, retransmission, queuing, cloud inference, or return delivery. Therefore the safety path must make decisions locally; cloud connectivity is for eventual synchronisation and fleet analytics, not the alarm.

**Bandwidth.** For a transparent lower-bound estimate, assume each scalar is a 32-bit value and ignore timestamps, packet headers, MQTT/TLS overhead, and door events. Temperature at 1 Hz is 4 bytes/s. Raw 3-axis vibration at 500 Hz is `500 × 3 × 4 = 6,000 bytes/s`. The combined rate is 6,004 bytes/s, or `6,004 × 86,400 = 518,745,600 bytes/day = 518.75 MB/day` using decimal MB. At ₹0.10/MB this is ₹51.87 per truck-day, roughly ₹4,409/day across 85 trucks if every raw value were uploaded. JSON and transport framing make the actual value larger. Edge processing publishes compact inference/alert events instead. At an illustrative 10 alerts/day × 1 KB each, that is 10 KB/day (₹0.001/truck-day); this is an example, not a measured incident rate. The on-truck simulator's 0.5 Hz vibration RMS is already an aggregate; the raw-rate calculation applies before that aggregation.

**Connectivity.** A cloud-only monitor loses its decision path during route gaps: no timely inference, no remote alert, and potentially missing chain-of-custody records. LogiEdge samples and evaluates locally, persists timestamped sensor summaries, model version, class, confidence, and alert state in a durable local log, and continues to raise local alarms while disconnected. A synchroniser uses a persistent outbox and sends events when MQTT/TLS connectivity returns; event IDs make retries idempotent and preserve ordering. The local log is authoritative during an outage.

**Privacy.** On-device feature extraction and inference keep high-rate temperature/vibration data within the truck. Only minimal, authenticated alert/health records need to leave the device, with encryption in transit, least-privilege device credentials, signed model updates, access control, and retention limits. This reduces third-party exposure but does not by itself prove a contract: storage encryption, key management, secure boot, access audits, and client-approved retention must be validated operationally.
